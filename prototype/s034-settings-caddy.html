Network · Caddy integration

Reverse-proxy exposed worktree ports through Caddy with automatic HTTPS. Optional — base port forwarding (localhost:<hostPort>) works with or without Caddy.

Enable Caddy reverse proxy
When enabled, every Expose action also writes a reverse_proxy snippet to configPath below and runs reloadCmd. The snippet maps the FQDN from the template to the host port allocated by palmux2.
caddy binary
Detected at server startup. If missing, the toggle above is disabled.
🔒 Available — caddy v2.7.6
FQDN template
Host name template for new public ports. Available placeholders: {repo} {branch} {port} {hostPort} — slashes are converted to - and the result is lowercased.
Preview · palmux2-feat-billing-5173.dev.example.com
Config path
Caddy snippet file. palmux2 owns this file (atomic write). Your main Caddyfile must import it — see docs/INSTALL.md.
Reload command
Run after each snippet update. Default uses caddy's reload-without-downtime endpoint. Configure to match your deployment (systemd unit, docker container, etc).

Network · Default isolation

Controls the global default for network isolation. Per-repo settings override this; per-worktree overrides per-repo.

Default: isolate network for new worktrees in newly-added repositories
When enabled, newly-added repositories default to "isolate network" for new worktrees. Existing repositories and worktrees are not affected. Per-repo settings override this; per-worktree overrides per-repo.
